## What runs when a person sends a message

1. The composer dispatches a send with the active bot and thread. The React store waits for pending execution settings, generates a send ID, posts the message and reconciles its optimistic row with the server receipt. [Composer](../../src/components/Composer.tsx) · [Store, send case](../../src/state/store.tsx)
2. The HTTP boundary resolves the caller's identity. The message route validates the target, checks ownership and recognizes duplicate sends. The host accepts, steers, queues or declines the operation according to the thread's current state. [Request authorization](../../server/request-auth.ts) · [Message route](../../server/routes/bot-messages.ts) · [Send identity](../../server/send-idempotency.ts) · [Host](../../server/index.ts)
3. The host builds the turn with the chosen provider, authorized context and tool grants. The driver adapter emits typed events. Ask-mode tool calls pause at a server-owned request. A synthetic provider or the same provider's real local model can exercise this boundary. [Driver contract](../../server/contracts.ts) · [Driver registry](../../server/drivers/builtIn.ts) · [Turn routing](../../server/turn-route.ts) · [Tool approval](../../server/drivers/chat-tool-approval.ts)
4. Conversation entries and observed activity feed the stored transcript and live events. SQLite holds the message index and separate assignment, event and inbox tables. A runtime transaction records a job transition. The remote service may already have acted when a process stops, which is why the restart path needs independent effect evidence. [Messages](../../server/message-db.ts) · [Runtime store](../../server/runtime/store.ts) · [Restart policy](../../server/runtime/runtime.ts)
5. The server streams events subject to the viewer's access and replay window. Slow connections may drop screen frames. A disconnected client can replay durable events or refresh state. React's live-event client handles reconnects. Electron exposes narrowly defined preload operations, isolates renderer context and guards window navigation. [SSE fanout](../../server/sse-fanout.ts) · [Replay](../../server/host/sse-replay.ts) · [Renderer client](../../src/lib/live-events.ts) · [Main process](../../electron/main.mjs) · [Preload](../../electron/preload.cjs)

The OS-specific desktop shell lives under `electron/`, the shared wire types under `shared/`, and the React app under `src/`. Core scheduling, drivers, browser sessions, storage and the approval broker live under `server/`. The companion, external connectors, Cloudflare broker and existing evaluation suites have separate entry points. The first sprint preserves the runtime architecture.

## Running the acceptance checks

Start in a clean worktree at the revision under test with `enterprise/` excluded. Install with `corepack pnpm install --frozen-lockfile`. Nested package scripts require the pinned `pnpm` command on PATH. The Windows audit used a temporary Corepack shim, disposable homes and the existing launcher’s independently chosen ports. The packaged smoke used separate Electron and server data directories and checked the process identity it received.

```powershell
$env:OMB_VITEST_E2E = 'host'
$env:OMB_VITEST_WORKERS = '6'
corepack pnpm test
```

That is the repository’s Windows host selection. Linux CI carries additional platform-independent end-to-end files. The package script uses `&&`, so run `broker:test`, `test:electron` and `test:packaged-server` individually after a failed Vitest run. The focused run included the named permission, memory, browser, renderer and runtime suites in the capability matrix, including their HTTP end-to-end files with host-only selection unset.

```powershell
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm build
corepack pnpm check:electron
corepack pnpm eval
corepack pnpm eval --golden
corepack pnpm package:win
```

For a local model, point `node --experimental-strip-types evals/runners/local-tool-approval.mjs --endpoint http://127.0.0.1:PORT/v1 --model MODEL --repeats 3 --seed experiment-1` at an explicitly chosen loopback provider. Each trial opens a fresh fixture and bot. The normal Ask card must identify the one permitted tool, and the tool must be idle before the decision. An allowed call must run exactly once after the decision and deliver the seeded receipt through the tool and the final answer.
